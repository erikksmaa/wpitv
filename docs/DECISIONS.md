## Rancangan lama yang telah digantikan

- **RBAC read-only lintas role lama** diganti matriks operasional `RBAC_ACCESS_MATRIX.md`; laporan RBAC lama sendiri menandai supersession 2 September. Perluas bacaan dengan Gate Equipment/Social dan policy Monthly/Live terbaru.
- **Status “Equipment belum dimulai” pada laporan rebuild 21 November** digantikan implementasi Inventory/Loans 23–24 November dan commit `f9510da` serta perubahan lokal. Baseline clone 24/35 tabel dalam proposal bukan jumlah tabel lokal sekarang (41).
- **Nama kolom Equipment proposal v3.x** digantikan kontrak schema aktual untuk runtime; contoh model_code/name, condition_notes/status_reason, storage_path/mime_type/file_size, actor_name_snapshot/event_name/occurred_at. Jangan membuat alias atau migration untuk memaksakan nama lama.
- **Implementasi Equipment sebelum rebuild** adalah arsip historis, bukan sumber runtime baru. Strategi migrasi histori/cutover/reset tetap keputusan terpisah, tidak terselesaikan oleh adanya tabel Equipment sekarang.
- **Live hanya dari Agenda** sudah diperluas dengan mode manual dan event manual_updated; kedua migration 18 November telah tercatat pada DB lokal.
- **README bercampur konflik dan checklist progres lama sebagai indeks utama** diganti enam dokumen handover ini. Angka tes lama tetap bukti historis dengan scope/tanggal, bukan kelulusan working tree terbaru.
- Nama berkas `EQUIPMENT_TECHNICAL_APPROVAL_v3.2.md` tidak cukup membuktikan approval eksekusi: isinya yang diperiksa juga memuat instruksi preflight dokumentasi. Baca laporan terkait dan bukti lingkungan; jangan menafsirkan judul sebagai izin DDL.

## Hal yang belum menjadi keputusan selesai

Persetujuan penerapan SQL Social pada target, penunjukan reviewer, schema/akun/manifest clone Equipment, migrasi histori/cutover, checkpoint Git dan deployment belum diselesaikan oleh handover ini. Visi/misi/sejarah/kepengurusan resmi memerlukan konfirmasi pemilik. Tambahan API Social, PDF server, portal peminjam atau perubahan approval membutuhkan scope baru, bukan asumsi roadmap.

Untuk keputusan baru, tambahkan tanggal, pemilik keputusan, alasan, dampak terhadap data/akses, artefak bukti dan keputusan lama yang digantikan. Jangan menuliskan rencana sebagai hasil penerapan.
